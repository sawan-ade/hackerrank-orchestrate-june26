# REPOSITORY ARCHITECTURE GUIDE: repository-guide.md

This document defines the folder structure, file organization, versioning conventions, and branch strategy for this research repository.

---

## 1. Directory Tree & Purpose

```
hackerrank-orchestrate-june26/
├── configs/            # Parameter configuration files (payoffs, agent parameters)
├── datasets/           # Preference and benchmark data (MT-Bench, RewardBench)
├── experiments/        # Source scripts running baseline and GT-Judge evaluations
├── figures/            # Compiled vector graphics and plots used in the paper
├── literature/         # PDF copies or notes of core reference papers
├── notes/              # Unstructured thought journals, feedback from supervisors
├── paper/              # LaTeX source code of the academic paper manuscript
├── results/            # Timestamps of raw experiment outputs (CSV, JSON logs)
├── src/                # Core production codebase
│   ├── agents/         # Proposer, Challenger, Critic, Arbitrator agents
│   └── games/          # Game solver engines, debate state loops, payoff functions
├── theory/             # Formally drafted mathematical definitions and proofs
├── assignments/        # Active tasks and milestone assignments for research staff
└── archive/            # Retired ideas, code blocks, or papers (DO NOT DELETE files)
```

---

## 2. Directory Policies

### `configs/`
- **Purpose**: Centralize all parameters that dictate game play.
- **Allowed**: `.yaml`, `.json` configuration files.
- **Forbidden**: Python script code, raw output logs.
- **Naming Rule**: `config_[game_mode].yaml` (e.g., `config_debate_evaluation.yaml`).

### `datasets/`
- **Purpose**: Host dataset snapshots.
- **Allowed**: `.jsonl`, `.csv`, `.parquet` datasets.
- **Forbidden**: Large binary blobs exceeding 100MB (use git-lfs or download links instead).
- **Naming Rule**: `[dataset_name]_[version].[ext]` (e.g., `mt_bench_v1.jsonl`).

### `results/`
- **Purpose**: Store raw experimental output logs for reproducibility check.
- **Allowed**: `.json`, `.csv` logs containing execution runs.
- **Forbidden**: Script files, manually edited tables (tables must be generated by scripts).
- **Naming Rule**: `[timestamp]_[model]_[run_id].json` (e.g., `20260715_gpt4o_run_01.json`).

### `src/`
- **Purpose**: Maintain the core multi-agent judge framework.
- **Allowed**: Python code files (`.py`), basic unit tests (`test_*.py`).
- **Forbidden**: Untracked configuration settings, notebook drafts (`.ipynb` must be in `notes/`).
- **Naming Rule**: Standard PEP 8 snake_case for filenames.

### `archive/`
- **Purpose**: Retain historical code, rejected proposals, and old experiments.
- **Allowed**: Any file format.
- **Forbidden**: Do not reference files inside `archive/` in core production code.
- **Naming Rule**: Prefix with retirement date, e.g., `archive/20260714_claim_adjudication/`.

## 3. Git Branch & Commit Strategy

### 3.1 Branch Layout
We maintain a strict branch structure to protect the integrity of the codebase:
- **`main`**: Production-ready, fully tested codebase. Must match the paper's reproducible code.
- **`dev`**: Integration branch for new features and experiments.
- **`feature/[name]`**: Short-lived branches for implementing specific mechanics (e.g., `feature/brier-score-game`).
- **`theory/[name]`**: Dedicated branches for writing and editing LaTeX equations or proofs in `theory/` or `paper/`.

### 3.2 Commit Message Rules
Every commit must be structured and descriptive:
```
[Type] (Related File/Section): Description of change

Scientific Impact: [How this change impacts games, theorem correctness, or benchmark numbers]
```

**Allowed Types**:
- `FEAT`: Adding new agent mechanisms or codebase logic.
- `MATH`: Modifying game payoff matrices, updating proofs or theorems.
- `EXP`: Running evaluations, adding new logs or charts to results.
- `DOC`: Writing READMEs, paper text, or guidebooks.
- `FIX`: Fixing bugs, resolving pipeline runtime errors.
